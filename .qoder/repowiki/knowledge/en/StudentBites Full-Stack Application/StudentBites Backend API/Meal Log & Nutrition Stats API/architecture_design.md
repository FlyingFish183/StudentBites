Three-file layering inside the backend: `LogRoutes.ts` is the Express request handler layer that validates inputs (using `jet-validators` and custom type guards like `isDateStr`, `isMonthStr`, `isMealType`) and delegates to service functions. `LogService.ts` owns CRUD over `prisma.mealLog` — adding logs from either a known dish or a custom entry, fetching month/day summaries, and deleting by ownership check. `StatsService.ts` computes aggregated stats by querying `mealLog` and pulling target values from `ProfileService.getTargets`. Dependency direction is strictly routes → services → Prisma/other services; routes never touch Prisma directly. Date handling is centralized through `PlannerService.formatDateOnly` / `parseDateOnly`, and HTTP error responses are raised via `RouteError` with `HttpStatusCodes` constants.
