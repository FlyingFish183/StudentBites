The module follows a thin-layered Express pattern: `AuthRoutes.ts` defines HTTP handlers for POST /api/auth/register, /login, /logout and GET /api/auth/me, performing request validation through `parseReq` from `./common/parseReq` and delegating business logic to `AuthService`. `AuthService.ts` is the sole business layer — it hashes passwords with bcryptjs (salt rounds = 10), throws `RouteError` with HTTP status codes from `HttpStatusCodes`, and persists data directly via `prisma.user` (imported from `@src/repos/prisma`). `UserRepo.ts` is a separate repository abstraction over a mock ORM (`MockOrm`) providing CRUD operations on an in-memory file store; it is not used by the auth service but exposes the same `IUser` type from `User.model.ts`. `User.model.ts` defines the `IUser` interface plus jet-validators schemas (`parseObject`, `testObject`) and a `new_` factory. Dependency direction is strictly routes → service → Prisma, while the repo layer sits alongside as an alternative persistence implementation sharing the model type.
