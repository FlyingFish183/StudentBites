Two-layer structure per domain: thin route files (`UserRoutes.ts`, `ProfileRoutes.ts`) handle HTTP request/response and input validation via `parseReq` from `./common/parseReq` plus `jet-validators`, then delegate to corresponding service files (`UserService.ts`, `ProfileService.ts`). Services encapsulate business logic — `UserService` delegates persistence to `UserRepo`, while `ProfileService` calls Prisma directly through `@src/repos/prisma` and uses shared calculation utilities from `@src/common/utils/nutrition`. Error handling is centralized via `RouteError` with `HttpStatusCodes` constants. The routes export handler functions as a const object, keeping Express middleware concerns separate from domain logic.
