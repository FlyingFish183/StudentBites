Tests are organized into three layers: (1) `planner.test.ts` and `users.test.ts` are top-level Vitest specs that import production code via `@src/*` aliases; (2) `support/agent.ts` bootstraps a shared Supertest agent bound to `@src/server`, runs once per suite via `beforeAll`, and calls `MockOrm.cleanDb()` to reset the database between suites; (3) `common/` holds reusable helpers — `comparators.ts` for order-independent user-array comparison, `error-utils.ts` for parsing JSON validation errors from `jet-validators`, and `supertest-types.ts` for a generic `TestRes<T>` type that augments Supertest's `Response.body`. Dependency direction is one-way: test specs depend on `support/` and `common/`, which depend only on third-party libraries (`supertest`, `jet-validators`) and never on each other. The integration tests exercise the full stack through HTTP while the planner tests exercise pure functions with deterministic fixtures.
