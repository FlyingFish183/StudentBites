The application is bootstrapped from `src/main.ts`, which starts the Express server defined in `server.ts` and conditionally launches the crawler scheduler (`crawlers/runner.ts`) outside of test environments. Domain logic is split into feature modules (auth, user/profile, planner, logs/stats) each exposing Express routes under `routes/`, business logic in `services/`, and data access through `repos/` which abstracts Prisma via a shared repository interface plus a JSON mock ORM for tests. All domains share `common/` utilities (constants, validators, nutrition helpers), and the Prisma schema in `prisma/schema.prisma` defines the single source of truth for users, profiles, ingredients, stores, dishes, meal plans, and logs. The entry point wires middleware (helmet, morgan, cookie-parser, JSON parsing), mounts the versioned API router, and serves static assets/views, making the server layer the sole orchestrator between HTTP, domain services, and the data layer.
